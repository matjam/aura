# CI and releases

This document covers the GitHub workflows, how a release is made with
release-please, where the version lives, and the self-extracting
archive and its installer. Read it before changing a workflow, making a
release, or touching `tools/make-sea.py`, `tools/binhex.py` or
`src/platform/macos9/sea`.

`.github/workflows/ci.yml` runs on every push to `main` and on pull
requests; `release.yml` makes releases. They need nothing outside the
repository: no disk images, no QEMU, no secrets.

## To make a release

Merge the pull request release-please keeps open ("chore: release
VERSION").

- `.github/workflows/release.yml` runs release-please on every push to
  `main`: it reads the Conventional Commits since the last release
  ([`conventions.md`](conventions.md)) and opens or updates that pull
  request, which sets `AU_VERSION` in `src/browser/credits.h` (the line
  marked `x-release-please-version`), `version.txt`, `CHANGELOG.md` and
  `.release-please-manifest.json`.
- When the pull request is merged, the same workflow tags the merge
  commit `vVERSION`, creates the GitHub release with the changelog
  entry as its notes, builds the archive and the Linux packages from that
  commit and attaches `Aura-VERSION.hqx`, `Aura-VERSION.sea.bin`,
  `aura_VERSION_amd64.deb` and `Aura-VERSION-x86_64.AppImage`.
- Do not push a tag or edit `AU_VERSION` by hand.
- To force a version, add `"release-as": "X.Y.Z"` to the package in
  `release-please-config.json` and remove it after that release.
- Before a release, test on the stock base as well as the Enforcer base
  ([`guest-testing.md`](guest-testing.md)).
- Before a release, make the longer fuzzing pass on `main` in the
  sanitizer tree: 3,000 Domato pages over ten new seeds (about 6
  minutes four seeds at a time) and `tools/fuzz-all.sh 120` with a new
  seed (about 13 minutes). [`fuzzing.md`](fuzzing.md), "The pass before
  a release", gives the commands and the table of seeds to add a row
  to. A report is fixed, with a regression, before the release pull
  request is merged.

## To build the archive locally

Run `./build.sh ppc`. It writes `build/ppc/dist/Aura-VERSION.sea.bin`
(MacBinary) and `Aura-VERSION.hqx` (BinHex 4.0) from
`build/ppc/dist/Aura`.

To pack another folder or stub:

```bash
tools/make-sea.py DISTFOLDER OUT.bin [--stub AuraSEA.bin] [--date SECONDS]
tools/binhex.py OUT.bin OUT.hqx
```

- `tools/make-sea.py --list OUT.bin` checks an archive and prints its
  entries and a SHA-256 of the unpacked contents.
- `tools/binhex.py --decode IN.hqx OUT.bin` and `--compare IN.hqx
  REF.bin` read BinHex back.

## To test the archive in the guest

Push the `.hqx` with `tools/guest-push.sh` (it arrives as a StuffIt
Expander text document) and open it: Expander is on the stock system,
asks for a folder because the disc is locked, and writes the installer
there. Or push the `.sea.bin`, which arrives as the application.

## To update a pinned action

Actions are pinned to a commit, with the release in a comment. To
update one, look up the release's commit (`gh api
repos/OWNER/REPO/commits/TAG -q .sha`) and change both.

## The CI jobs

| Job | What it does |
|---|---|
| `host` | runs `./build.sh test` on Ubuntu (GCC) and macOS (Apple Clang) |
| `sanitize` | runs the tests on Ubuntu under Clang's AddressSanitizer and UBSan (with `float-cast-overflow` named, as in [`building.md`](building.md)), with leak detection off |
| `toolchain` | builds Retro68 when the cache has none |
| `linux` | runs `tools/package-linux.sh` on Ubuntu (`build-linux.yml`, a reusable workflow) and uploads `aura_VERSION_amd64.deb` and `Aura-VERSION-x86_64.AppImage` as artifacts named `Aura-VERSION-SHORTHASH-deb` and `Aura-VERSION-SHORTHASH-appimage`; see [`gtk.md`](gtk.md), "Packaging" |
| `ppc` | runs `./build.sh ppc` and uploads the two archives as artifacts named `Aura-VERSION-SHORTHASH-hqx` and `Aura-VERSION-SHORTHASH-sea-bin` |

- Leak detection is off because several tests do not free everything at
  exit; macOS, where the sanitizer build is run by hand, does not
  detect leaks either.
- `toolchain` and `ppc` are in `build-ppc.yml`, a reusable workflow.

## The toolchain cache

`~/.local/opt/retro68` is cached under the key `retro68-Linux-` plus
the hash of `toolchain/build.sh`. To rebuild the toolchain in CI,
change that script (the pinned commit, say). A cold build takes about
15 minutes; a newer push does not cancel it. A cache made on a branch
serves that branch only; `main`'s serves every branch and pull request.

## The version

The version lives in one place, `AU_VERSION` (three numbers, with
one-digit minor and bug-fix parts so that it fits the BCD byte of a
`vers` resource). These read it:

- the About box and the user agent;
- both applications' `vers` resources (generated by CMake from
  `aura_vers.r.in` and `sea/sea_vers.r.in`);
- `tools/version.sh`;
- the archive's file names.

A `feat:` raises the minor part, a `fix:` or `perf:` the last part;
before 1.0 a breaking change raises the minor part.

## release-please's settings

- `release-please-config.json`: release type `simple`; `bootstrap-sha`
  is the commit where changelog collection starts, so the history
  before Conventional Commits is not read; `initial-version` makes the
  first release 0.3.0. Both stop mattering after the first release.
- `.release-please-manifest.json`: the last released version, written
  by release-please.
- It needs the repository setting Settings > Actions > General > "Allow
  GitHub Actions to create and approve pull requests".
- A release made with the workflow's token starts no other workflow,
  which is why the build is a job of `release.yml` (it calls
  `build-ppc.yml`, as `ci.yml` does).

## The archive

The archive is one Mac OS 9 application, "Aura VERSION Installer"
(`src/platform/macos9/sea`, creator `AuSX`).

- `make-sea.py` appends the packed folder to the stub's data fork,
  after the PowerPC code, and changes the stub's `cfrg` resource from
  "the code runs to the end of the fork" to the code's length, so that
  Mac OS does not load the archive with the code.
- Each file carries its path, type, creator, Finder flags, dates and
  both forks, each fork as a raw deflate stream with a CRC-32;
  `sea_archive.h` gives the layout.
- The packer maps host files as `tools/guest-push.sh` does (`.bin` is
  MacBinary, fonts become `tfil`/`AURA`, licences become SimpleText
  documents).
- Every date is the last commit's (or `SOURCE_DATE_EPOCH`), so one
  machine builds the same bytes from the same commit. A Linux and a
  macOS build of one commit differ in the application and the stub: the
  same code, with functions at other addresses.

## The installer

The installer is `sea.c`.

- It asks for the folder with `StandardPutFile` (starting beside
  itself, with the first free name of "Aura", "Aura 2" and so on; it
  never replaces an item).
- It writes the files through `sea_archive.c` with two fixed buffers
  (16 KB in, 32 KB out) and Aura's inflate decoder, sets Finder info
  and dates, checks every CRC, and sends the Finder an Open Documents
  event for the new folder.
- On an error or Command-period it deletes the folder it made and shows
  what failed.
- Its partition is 1 MB.

`sea_archive.c` is portable: `tests/tools` builds `sea_extract` from it
and checks it on the host against the packer, with damaged copies
(`tools_sea_extract` in ctest), beside the self-tests of `binhex.py`,
`make-sea.py` and `finder-flags.py`.
